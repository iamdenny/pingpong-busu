# BUSU 제품 스펙

## 1. 문서 상태

- 기준 시점: 2026-08-13
- 상태: 구현된 MVP 기준
- 제품 언어: 한국어
- canonical implementation: `apps/web`, `packages/*`, `supabase`
- 제품 원칙: BUSU는 공식 부수를 판정하지 않고 공개 대회 기록의 판단 근거를 모은다.

코드와 이 문서가 다르면 테스트된 코드 동작을 확인하고, 의도된 변경이면 같은 작업에서 이 문서를 갱신한다.

## 2. 사용자와 핵심 문제

주 사용자는 대회 참가 전 상대나 참가자의 최근 관측 부수·소속·입상 기록을 확인하려는 탁구인과 운영자다. 정보가 여러 대회 사이트에 분산되어 있고 출처별 체계가 다르므로, BUSU는 다음 정보를 한 화면에 모은다.

- 이름이 같은 선수 후보
- 기록 기반 추정 지역과 당시 소속
- 최근 관측 부수와 부수 체계
- 전체 참가 이력과 4강 이상 입상 이력
- 출처별 차이, 마지막 확인 시각, 원문 URL

## 3. 범위와 비목표

### 현재 범위

- 이름 검색과 동명이인 후보 분리
- 부수 체계별 최근 관측값 요약
- 활성 출처별 실시간 조회 진행 표시
- 선수 상세의 최신순 대회 이력, 입상 필터, 출처 비교
- demo, local live, hosted Supabase 실행 모드
- 공개 HTTP 출처 adapter와 synthetic fixture 검증
- Supabase RLS/public view/RPC/Edge Function
- GitHub Pages 및 Supabase 배포 자동화

### 비목표

- 공식 부수 확정 또는 자동 승급 판정
- 이름만으로 선수 자동 병합
- 로그인·회원가입·결제·광고
- BAND scraping, CAPTCHA 또는 접근제어 우회
- 전화번호, 이메일, 전체 생년월일, 주소 수집
- 원본 HTML·이미지·PDF 영구 저장

## 4. 사용자 흐름

### 4.1 홈

1. 사용자는 선수 이름을 입력한다.
2. 검색 출처 요약은 활성 출처 수와 전체 공개 출처 수를 작게 보여준다.
3. `상세`를 열면 출처명, 상태, 원문 URL을 목록으로 보여준다.
4. BAND는 사용자 출처 목록에서 제외한다.
5. 에어핑퐁·오케이핑퐁은 운영 스위치가 활성일 때 승인 범위의 공개 선수 검색을 조회하고, 긴급 중지 시 검색어가 포함된 원문 링크를 제공한다.
6. 예시 검색어 아래에는 현재 브라우저에 저장된 최근 검색어를 최신순으로 최대 10개 표시한다.
7. 같은 검색어를 다시 검색하면 중복을 만들지 않고 맨 앞으로 이동하며, 사용자는 전체 기록을 즉시 삭제할 수 있다.
8. 모든 페이지 하단에는 배포 버전을 작게 표시한다. production은 `YYYY.WEEK.SEQ`, 버전이 주입되지 않은 로컬 개발은 `개발`로 표시한다.
9. 홈 히어로는 한 줄 제목 아래와 검색창 사이에 독립된 3D 탁구 랠리 스테이지를 표시한다. 공은 매 타구 전 테이블에 한 번 튀고 좌우 위치에 맞춰 포핸드·백핸드로 받으며, 드라이브·커트의 스윙과 상회전·하회전을 구분한다. 드라이브는 라켓을 위에 들었다가 공으로 내려 앞으로 밀어내며 라켓면을 약 20도 앞으로 숙이고, 커트는 위에서 아래로 끊으며 라켓면을 약 20도 연다. 타구는 공이 온 레인을 그대로 지키는 직선 코스와 반대편으로 보내는 대각 코스를 섞어 사용한다. 같은 코스와 같은 타법은 연속 2회까지만 허용하고 세 번째 타구에서는 좌우 코스와 드라이브·커트를 각각 반대로 강제해 랠리가 한 패턴에 갇히지 않게 한다. 사용자는 마우스 드래그나 한 손가락 터치로 고정 바닥을 제외한 랠리 월드를 3축으로 회전할 수 있으며, 테이블 밑면이 카메라에 노출되는 회전은 제한한다. 빠르게 튕겨 놓으면 마지막 회전 속도를 이어받아 관성으로 돌다가 약 1~2초에 걸쳐 멈추고, 회전이 멈춘 뒤 5초가 지나면 기본 시점으로 부드럽게 돌아온다. 마우스 휠, 트랙패드 핀치, 두 손가락 터치로 기본 배율의 0.8배에서 2.2배까지 확대·축소할 수 있고 배율도 같은 5초 복귀에 함께 돌아온다. 두 손가락은 한 제스처로 회전과 확대를 동시에 수행하며, 손가락이 하나 떨어지면 남은 손가락이 회전을 그대로 이어받는다. 배율 한계에 닿은 마우스 휠은 소비하지 않고 페이지 스크롤로 넘겨 히어로가 스크롤을 가두지 않는다. 공이 라켓과 테이블에 맞을 때 타구음을 낸다. 기본은 켜짐이고 장면 위의 스피커 아이콘 버튼으로 끄고 켜며, 선택은 브라우저에 저장해 다음 방문에도 유지한다. 브라우저는 첫 사용자 동작 전에는 소리를 허용하지 않으므로 실제 재생은 페이지에서 처음 누르거나 입력한 시점에 시작한다. 버튼은 켜짐과 꺼짐 아이콘을 바꿔 보여주고 `타구음 켜기`·`타구음 끄기`를 접근 이름으로 제공한다. 소리는 오디오 파일 없이 합성하고 라켓은 밝고 짧게, 테이블은 낮고 조금 길게 울린다. 장면은 접근성 트리에서 제외하되 타구음 버튼은 제외하지 않으며, WebGL 미지원 시 장면과 버튼을 함께 생략하고, 모션 줄이기 환경에서는 자동 랠리를 정지한다.

### 4.2 검색 결과

1. 저장된 후보를 먼저 조회한다.
2. production refresh가 켜져 있으면 이름이 2자 이상일 때 활성 출처를 각각 조회한다.
3. 화면은 전체/완료/조회 중 출처 수와 현재 출처명을 독립적으로 갱신한다. 최초 저장 결과가 0건일 때만 진행 중인 출처별 상태를 자동으로 펼치고, 저장 결과가 있으면 처음부터 요약만 보이도록 접어 둔다. 접힌 채 조회 중이면 실제 완료 비율 진행 바를 표시하고 출처가 완료될 때마다 채움 폭을 부드럽게 보간한다. 은은한 배경 스캔은 접힘 여부와 무관하게 조회 중인 동안 유지한다. 모든 조회가 끝나면 자동으로 접으며 사용자는 언제든 상세를 펼칠 수 있다.
4. 출처 하나가 실패해도 저장 결과와 다른 출처 결과를 유지한다.
5. 상단 `현재 추정 부수`는 오픈부수·통합부수·지역부수·디비전부수를 각각 행으로 묶는다. 통합부수는 일반 숫자·희망·새싹 관측을 첫째 줄, 여자 숫자·여자희망·여자새싹 관측을 둘째 줄로 나누고, 각 줄 안에 `부수·입상 건수·참가 건수` 항목을 가로로 표시한다. 입상 건수는 0건이면 기본 파랑을 유지하고 1건 이상일 때만 주황 계열로 강조하며, 참가 건수에는 이 강조를 적용하지 않는다. 이 집계와 검색 카드의 최근 관측 부수는 개인전 기록을 우선하며, 복식·단체전 또는 종목명에 `혼합`·`혼성`이 표시된 기록은 제외한다. 제외한 기록은 원문 출전·입상 이력에서 계속 제공하되, 검색 카드의 입상 성적과 선수 상세의 종목 표시에 `단체`·`복식`·`혼성` 표식을 붙여 집계에서 빠진 이유를 밝힌다. 동명이인 후보가 2건 이상이고 참여 편집으로 검증된 별칭이 있으면 별칭별 영역과 `미분류 기록` 영역을 먼저 나누고 각 영역 안에서 부수를 집계한다. 항목은 `선수부 → 0부 → 1부 → 2부 …`의 부수 오름차순으로 정렬하고 디비전은 `T1 → T2 …` 순서를 사용하며, 숫자가 없는 값은 숫자 부수 뒤에 둔다. `women` 기록은 통합부수의 둘째 줄에서 `여자6부`처럼 구분하고, 체계를 판단할 근거가 없는 기록만 `체계 확인 필요` 행에 남긴다. 한 줄의 항목이 화면보다 많을 때는 전체 표가 아니라 해당 줄의 세부 정보만 좌우로 이동한다. 4강 이상은 입상, 나머지는 참가로 서로 겹치지 않게 집계하며 각 부수를 누르면 해당 별칭 영역 안에서 같은 체계와 부수의 기록이 있는 후보만 남기고 결과 목록으로 이동한다. 단일 후보이거나 검증된 별칭이 없으면 기존 전체 집계를 유지한다.
6. 후보 수 단위는 `명`이 아니라 `건`을 사용한다.
7. 결과 제목에는 `후보`라는 단어를 붙이지 않는다.
8. 검색 후보가 한 건 이상이면 `별칭으로 기록 묶기`를 제공한다. 동명이인이 2건 이상이면 소속과 활동 지역 확인 경고를 함께 표시한다.
9. 후보 목록은 기본 `입상` 탭과 `출전` 탭으로 나누며 각 탭에 후보 수를 표시한다. 탭을 바꾸면 선택 pill과 결과 패널이 같은 방향으로 좌우 전환되고, 모션 줄이기 환경에서는 전환 시간을 사실상 제거한다.
10. 4강 이상 입상 기록이 한 건 이상인 후보는 `입상`, 입상 기록 없이 참가 기록만 있는 후보는 `출전`에 표시한다.
11. `이름 지역` 검색은 첫 단어를 선수 이름, 나머지를 지역 필터로 해석한다. 외부 출처에는 선수 이름만 전달한다.
12. 입상 후보는 최신 입상부터 등수와 그 다음 줄의 대회일을 최대 두 건 표시하고 남은 기록 수를 함께 표시한다.
    12-1. 이미 같은 선수로 연결된 교차 출처 결과가 실제 대회일·대회명·정규화한 종목·부수 체계와 값·입상 결과까지 같으면 입상 건수와 최근 입상 목록에서는 한 건으로 표시하고, 출처가 여러 곳임을 함께 표시한다. 날짜가 없거나 한 출처 안에서 충돌하면 각각 유지한다.
13. 반복되는 상세 버튼 없이 후보 카드 전체를 해당 후보 상세 링크로 제공한다.
14. 후보 카드는 최근 확인일을 상단 상태 영역에 배치하고 내부 여백과 구분 간격을 작게 유지해 한 화면에서 여러 후보를 비교할 수 있게 한다.
15. 검색 후보가 한 건 이상이면 참여자는 `별칭으로 기록 묶기`에서 별칭을 직접 입력하고 공개 기록을 별칭 그룹에 배정할 수 있다. 단일 후보는 유일한 별칭 그룹에 기본 배정하며, 같은 이름 후보가 여러 건이면 소속과 활동 지역을 확인한 뒤 사용자가 직접 배정하고 후보 수 상한 없이 확실하지 않은 기록은 미분류로 남긴다. 후보가 여러 건이면 배정 영역에서 `전체 N건 한 사람으로`와 `전체 해제`로 한 번에 배정하거나 되돌릴 수 있다. 이 일괄 동작은 배정 상태만 바꾸며 별칭 입력·확인 동의·제출은 그대로 거친다. 전체 후보가 하나의 별칭에 배정되면 확인 문구가 전체를 한 사람으로 묶는다는 사실과 되돌릴 수 있음을 함께 명시한다.
16. 참여자는 비밀번호나 확인 코드를 입력하지 않는다. 브라우저가 익명 편집자 ID를 자동 생성·보관하되 이 값은 인증이나 원복 권한으로 사용하지 않는다.
17. 별칭 한 개 이상에 기록이 배정되면 관리자 승인 없이 즉시 반영한다. 한 사람만 확실히 아는 경우 해당 기록에만 별칭을 붙이고 나머지는 미분류로 남길 수 있다. 같은 별칭 안의 기록은 하나의 선수로 연결하고 별칭 간에는 분리하며, 원본 선수·대회 기록과 변경 전 연결을 보존한다.
18. 기록 후보에는 지역·소속·부수와 함께 최근 출전 대회명과 출처에 표시된 원문 종목명을 최대 두 건 노출한다.
19. 검색 화면은 참여 편집 이력, 변경 근거, 후보별 별칭과 상태를 공개하며 잘못된 최신 분류 전체를 누구나 근거를 남겨 원자적으로 되돌릴 수 있다. 별칭은 공개 기록을 묶고 구분하는 이름일 뿐 본인 인증·실력·부수·공식 등급이 아님을 화면에 명시한다.
20. 각 결과 탭은 참여 편집으로 연결된 동명이인을 먼저 표시한다. 나머지 입상 후보는 최신 입상일, 출전 후보는 `대회일 → 게시일 → 확인 시각` 기준 최신순으로 표시하며, 날짜가 없을 때는 해당 탭 기록의 확인 시각만 사용한다. 검색 카드는 입상 등수·날짜·대회명·원문 종목명 또는 최근 출전 대회명·원문 종목명·날짜를 함께 보여주고, 기록 기반 지역과 소속은 같은 시간축에서 가장 최근의 비어 있지 않은 공개 관측값을 사용한다. 미래 대회 신청 기록은 원문 상세에는 보존하되 현재 관측 부수와 입상·출전 요약에는 포함하지 않는다. 복식·단체·혼합·혼성 기록은 일반 입상·출전 요약에는 유지하되 카드의 최근 관측 부수와 상단 현재 추정부수에는 포함하지 않는다. 같은 최신 개인전 대회일에 여러 체계가 있으면 카드의 단일 관측값은 통합·여자부수를 오픈부수보다 우선한다.

### 4.3 선수 상세

- 상단 요약은 하나의 섹션에서 최근 관측 부수와 통합부수 기록을 한 줄로 보여주고, 같은 섹션 안에 `부수별 입상·참가 기록`을 이어 붙인다. 이 표는 `개인전`과 `단체전` 두 묶음으로 나누며, 개인전은 검색 화면의 `현재 추정 부수`와 같은 기준으로, 단체전은 복식·혼성을 포함한 집계 제외 기록으로 표시한다. 두 묶음 모두 선수 상세가 불러온 공개 기록에서 계산하고 후보 필터 없이 읽기 전용으로 제공한다. 소속·지역을 확인하지 못했다는 배지는 표시하지 않는다. 통합부수 기록은 출처 배열의 첫 요약값이 아니라 선수의 전체 공개 이력에서 최신 유효 `integrated`·`women` 관측을 선택하며, 최근 관측 부수와 동일하게 과거 지역부수·미래 대회·복식·단체·혼합·혼성 기록을 제외한다.
- `출처별 상태`는 출처 수와 저장 기록 우선 안내만 보이는 기본 접힘 상태로 시작하며, 홈·검색 결과와 같은 `CollapsibleContent` 효과로 펼치고 다시 접을 수 있다.
- `입상 이력 (4강 이상)`, `전체 이력`, `출처 비교` 탭 순서로 제공하며 입상 이력을 기본으로 표시한다.
- 대회 이력은 desktop table과 mobile card로 표시한다.
- 각 기록은 출처 대회에 표시된 종목명을 축약하거나 별도로 재분류하지 않고 전체 표시한다.
- 각 기록은 당시 소속·부수·결과·출처 원문을 제공한다.
- 같은 결과를 여러 출처가 제공하면 이력은 한 행으로 표시하고 그 행에서 모든 출처 원문 링크를 제공한다.

## 6. 도메인 규칙

### 6.1 선수 identity

- 검색 결과의 같은 이름은 같은 사람이라는 뜻이 아니다.
- 출처별 identity는 source external ID를 우선하고, 없으면 정규화 이름과 소속 또는 대회 근거로 분리한다.
- 이름 일치만으로 실행되는 자동 merge는 금지한다. 사용자가 각 기록을 서로 다른 탁구 별칭 그룹에 명시적으로 배정한 경우에만 그룹 내부 연결과 그룹 간 분리를 실행한다.
- 지역 추정값은 identity 병합의 단독 근거가 될 수 없다.
- 별칭은 한글이나 영문을 포함한 2~20자로 직접 입력하며 정규화 이름이 같은 활성 후보끼리는 중복하지 않는다. 전화번호·이메일·전체 생년월일·주소 형태와 제어 문자·HTML 문자를 거부하고 실제 플레이 스타일이나 실력 판정으로 사용하지 않는다.
- 동명이인 기록 분류는 별도 근거 입력 없이 선택한 별칭과 기록만 즉시 반영한다. 잘못된 분류의 원복에는 공개 이력에 남길 근거를 입력한다.
- 브라우저가 생성한 익명 편집자 ID 원문은 서버에 저장하지 않고 서버 HMAC으로 변환한다. 이름별 호출 제한에는 정규화 이름을 별도로 함께 사용한다. 사용자가 기억할 비밀번호·코드나 휴대폰 번호·생년월일은 입력하지 않는다.
- 같은 정규화 이름에 속한 후보만 한 편집으로 묶을 수 있고 후보 총수에는 고정 상한을 두지 않는다. 후보 근거 조회는 최대 100건씩 분할한다. 요청 원점·편집자 예산은 모든 시도에, 전체 예산은 성공하는 편집·원복 트랜잭션에 원자적으로 적용해 과도한 제출과 무효 요청을 이용한 전체 차단을 함께 방지한다.
- 참여 편집은 즉시 반영하고 이전 값, 선택 후보, 근거, 처리 시각을 공개 감사 이력에 남긴다.
- 승인된 대표 소속·활동 지역은 원문 수집 기록을 덮어쓰지 않고 canonical metadata로 별도 관리한다.
- 출처에 표시된 소속은 원문 근거로 보존하되 crawler가 대표 소속이나 canonical club으로 자동 승격하지 않는다.
- 참여 편집은 선수나 대회 기록을 삭제하지 않고 출처 identity 연결을 이동하며, 병합 전 연결·상태·익명 처리자 hash·사유를 보존한다.
- 잘못된 병합의 원복은 저장된 스냅샷과 현재 상태가 일치할 때만 수행하고 후속 병합이 있으면 최신 작업부터 역순으로 원복한다.

### 6.2 지역

- 출처가 제공한 명시적 지역을 우선한다.
- 없으면 대회명·종목명에서 도·특별시·광역시·특별자치도, 시·특례시·군·구를 정규표현식으로 추출한다.
- 일부 접미사 생략 지명은 검토된 별칭 사전만 사용한다.
- AI 추론은 사용하지 않으며 UI에는 `기록 기반 추정`이라고 표시한다.

### 6.3 기록 시간축

정렬 키는 다음 순서를 사용한다.

1. 대회 개최일 `tournaments.held_on`
2. 출처 게시일 `results.source_published_on`
3. 마지막 확인 시각 `results.last_checked_at`

날짜가 없는 기록은 날짜가 있는 기록 뒤에 둔다. 게시일을 쓴 경우 UI에 `게시일`을 표시한다.

### 6.4 입상

- 입상: 우승, 준우승, 1위, 2위, 3위, 2강, 4강
- 참가 이력: 8강 이하, 예선/본선 진출, 예선·조별 문맥의 순위, 단순 참가
- 참가 이력도 전체 이력에는 남지만 입상 건수에는 포함하지 않는다.
- 검색 요약은 각 입상의 `rank`와 `대회일 → 게시일` 기준 날짜를 최신순으로 제공한다.

### 6.5 부수 체계

판정 우선순위는 다음과 같다.

1. `T1`~`T7` 또는 `디비전` 명시 → `division`
2. 근거가 확인된 대회별 수동 override → 지정된 체계
3. `지역부수` 또는 종목 내부의 `지역`, `지역남성`, `지역여성`, `지역혼성` 명시 → `regional`
4. 명시적 지역 종목이 아닌 참가 종목 또는 관측 부수에 `여자` 또는 `여성` 포함 → `women` (일반 `integrated`·`open`·미분류 관측보다 우선)
5. `통합부수`처럼 체계가 명시됨 → 명시된 체계
6. 대회·종목에 `오픈` 명시 → `open`(단, 종목 내부 지역 구분은 3번 적용)
7. 일반 숫자 또는 문자 부수 → `integrated`
8. 부수 값이 없거나 해석 불가 → `unknown`

지역별 날짜 규칙은 대회 지역과 개최일을 모두 확인한 경우에만 적용한다. 대회명에 `오픈`이 있더라도 종목 내부에 `지역`, `지역남성`, `지역여성`, `지역혼성` 구분이 명시되면 날짜와 관계없이 지역부수다. 지역 또는 날짜가 없으면 명시적 지역 종목을 제외한 일반 숫자 부수를 통합부수로 두는 기존 기본값을 유지한다. 동일 숫자라도 서로 다른 체계는 합산하지 않는다.

전환일 이전 또는 대회별 예외인 지역부수 기록은 검색과 상세 이력에 보존하고 상세 대회일 옆에 통합부수 시행 이전 안내 또는 예외 설명을 표시한다. 이 과거 기록과 아직 개최되지 않은 미래 대회 신청 기록은 검색 상단 `현재 추정 부수`, 최근 관측 부수, 체계별 입상·참가 집계, 검색 카드의 입상 건수·최근 입상·최근 출전 요약에는 포함하지 않는다.

근거가 확인된 수동 override는 일반 추론보다 우선하고 버전 관리한다. 현재 제18회까지의 분당구청장기는 지역부수로 분류하며, 제19회 이후와 이름이 다른 분당구 대회에는 적용하지 않는다. 이후 확인되는 예외도 특정 대회명과 회차를 명시해 추가한다. 지역별 기준일과 근거는 [부수 체계 전환 기준](division-transition-rules.md)에서 관리한다.

## 8. 갱신과 중복 방지

- 브라우저는 외부 출처를 직접 호출하지 않고 `refresh-player` Edge Function을 호출한다.
- 검색 화면은 활성 출처별 요청을 분리하고 시간 초과·접근 차단·구조 변경·인증 실패 등 실제 실패 원인을 보여준다.
- 자동 검색 요청은 같은 이름의 최근 6시간 성공 결과를 재사용한다. 일반 출처의 실패 행은 명시적 수동 재시도만 `force=true`로 cache를 우회한다.
- 아이핑은 브라우저 요청에서 외부 fetch를 실행하지 않고 선수 이름 형태를 확인한 뒤 6시간 freshness·중복 작업·분당 신규 4건·활성 12건 제한을 적용한 private queue에 등록한다. 화면은 기존 저장 결과와 `수집 예약됨`, 보통 10분 안에 반영되고 자동으로 갱신된다는 안내를 함께 표시하고 아이핑 수동 재시도는 제공하지 않는다. 예약 상태인 동안 화면은 1분 간격으로 최대 20회까지 상태를 다시 확인하고, 수집이 끝나면 재검색 없이 `최근 확인 완료`와 갱신된 기록을 보여준다. 진행 중 작업이 있거나 최근 결과가 신선하면 enqueue RPC가 예약 예산을 올리기 전에 조기 반환하므로 이 재확인은 큐 예산과 외부 요청을 소모하지 않는다. main 예약 worker는 5분마다 가장 오래된 작업 하나를 4분 lease로 처리하며, transient 오류만 15~60분 backoff로 최대 3회 시도한다. 인증·구조·접근 차단은 terminal 처리해 backlog를 멈추고 6시간 회로를 연다.
- 일반 동기 출처에는 `출처 + 정규화 검색어`별 5~60초 범위의 최소 호출 간격과 1분당 최대 4회 제한을 적용한다. 에어핑퐁은 출처 단위 분당 실제 요청 6회 예산을 적용한다. 제한 응답과 에어핑퐁의 명시적 `source_timeout`은 남은 밀리초를 반환하며 화면은 최소 5초 간격으로 최대 2회 자동 재시도한다. 그 밖의 일반 실패에는 5초 쿨다운·화면당 최대 3회의 작은 수동 재시도 버튼을 제공한다.
- 실패 상태에는 허용 목록의 안전한 `last_error_code`만 저장하고 검색어·원문 오류·쿠키·HTML은 저장하지 않는다. 다음 성공 시 이전 오류 코드를 지운다.
- DB 또는 서버 환경 변수에서 비활성인 출처는 조회 대상에서 제외하고, 두 설정이 일치하지 않으면 `연동 꺼짐`으로 표시한다.
- `CRAWL_LIVE`, 출처별 환경 변수, DB `sources.enabled`가 모두 true여야 외부 요청한다.
- adapter가 날짜 범위 검색을 제공하지 않으면 공개 검색 결과를 다시 받아 natural/content hash로 비교한다.
- 신규·변경 기록만 insert/update하고 동일 기록은 확인 시각만 갱신한다.
- 사라진 기록은 즉시 삭제하지 않는다.

- 아이핑 요청 원점은 원본 IP 대신 service-role HMAC으로만 구분하고 10분 4건으로 제한하며 budget hash는 하루 뒤 삭제한다.

## 9. 실행 모드

| 모드       | 선택 조건                                                | repository                 |
| ---------- | -------------------------------------------------------- | -------------------------- |
| Test/Demo  | test, `VITE_APP_MODE=demo`, 또는 Supabase 공개 설정 누락 | `DemoPlayerRepository`     |
| Local live | Vite dev + `VITE_DEV_LIVE_SEARCH=true`                   | `DevLivePlayerRepository`  |
| Hosted     | URL/publishable key 존재, demo 아님                      | `SupabasePlayerRepository` |

hosted production에서 실시간 갱신 UI는 `VITE_SOURCE_REFRESH_ENABLED=true`일 때만 켜진다. hosted development는 별도 Supabase 프로젝트와 합성 seed를 사용하고 실출처 갱신을 켜지 않는다.

production의 검색엔진 공개 목록은 배포 시 경량 `public_player_seo_manifest`를 publishable key로 끝까지 페이지 조회한 스냅샷이다. 활성 공개 출처가 하나 이상인 유효 선수만 정적 상세 HTML과 sitemap에 포함하며, 새 선수와 변경된 메타데이터는 다음 배포에서 반영한다. 검색 결과 URL은 검색어와 관계없이 canonical `/search`를 사용하고 색인하지 않는다.

선수 상세 초기 HTML에는 같은 스냅샷의 이름·동명이인 별칭·지역·소속·입상 수·출처 수를 요약 본문으로 심고, `ProfilePage`와 `Person`, 상위 목록까지의 `BreadcrumbList` 구조화 데이터를 함께 넣는다. 홈의 `WebSite` 스키마는 사이트 엔터티 참조로 모든 문서에 그대로 남긴다. 요약 본문은 `createRoot` 마운트 시 React가 대체하므로 사용자에게 보이는 화면은 변하지 않는다.

같은 스냅샷으로 `/directory/` 정적 색인을 함께 생성한다. 선수를 이름 초성 14개 그룹(ASCII slug)으로 나누고 그룹마다 200명씩 페이지를 끊어, 모든 공개 선수가 홈에서 세 번의 링크 이동 안에 도달한다. 그룹 페이지는 자기 그룹의 모든 페이지 번호를 함께 링크한다. 색인 페이지는 SPA 라우트가 아니므로 애플리케이션 번들 없이 렌더링하며, 앱 페이지는 초기 HTML의 `#root`와 공통 footer 양쪽에 색인 진입 링크를 둔다. `#root`의 링크는 `createRoot` 마운트 시 React가 대체한다.

운영 제품 분석은 `VITE_UMAMI_SCRIPT_URL`과 `VITE_UMAMI_WEBSITE_ID`가 모두 유효할 때만 셀프 호스트 Umami tracker를 불러온다. 페이지 조회에서는 query string을 제외하고, 검증된 검색어와 최소한의 클릭·완료 이벤트만 [제품 분석 이벤트 사전](./analytics.md)에 따라 전송한다. 설정 누락이나 전송 실패는 사용자 흐름을 중단하지 않는다.

## 10. 보안과 개인정보

- 브라우저에는 Supabase URL과 publishable key만 둔다.
- service role key, Supabase PAT, crawler secret은 Edge/CI trusted environment에만 둔다.
- Edge Function은 허용된 publishable key를 확인하고 내부 DB 작업은 service role로 수행한다.
- 외부 응답은 runtime schema 검증 후 필요한 공개 필드만 정규화한다.
- 전화번호, 이메일, 전체 생년월일, 주소, 원본 응답 본문은 저장하지 않는다.
- 로그인, CAPTCHA, 접근제어를 우회하지 않는다.
- 최근 검색어는 서버나 외부 분석 서비스에 별도 저장하지 않고 현재 브라우저 `localStorage`에 최대 10개만 보관한다.

## 11. 품질과 배포

모든 변경은 다음 게이트를 통과해야 한다.

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

parser 변경은 synthetic fixture test가 필수다. 주요 사용자 흐름은 Playwright smoke로 검증한다. `main` push는 GitHub Pages를 빌드하고, production secret/variable이 준비된 경우 production Supabase migration과 Edge Function을 배포한다. Pages production build는 공개 선수 manifest 설정·응답·schema와 비어 있지 않은 결과를 필수로 검증하고 하나라도 실패하면 정적 산출물을 게시하지 않는다. development Supabase는 main의 수동 workflow에서만 migration과 반복 가능한 합성 seed를 적용하며 production project ref와 같으면 실패해야 한다. 제품 버전은 루트 `package.json`의 `YYYY.WEEK.SEQ` 한 곳에서 관리한다. Pages workflow는 검증과 build가 끝난 뒤 같은 버전의 태그·GitHub Release·자동 릴리즈 노트를 생성하고, 그 release가 성공한 경우에만 사이트를 게시한다.

## 12. 현재 제약과 다음 단계

- 출처 운영 정책은 바뀔 수 있어 활성화 근거를 주기적으로 재검토해야 한다.
- 수동 재시도의 `force=true`는 공개 abuse control을 강화하기 전까지 출처별 최소 호출 간격과 계정 단위 예산에 의존한다.
- 탁구 별칭 기반 동명이인 참여 편집, 공개 감사 이력과 사용자 원복을 제공한다. 향후 합의·이견 표시와 abuse control을 강화한다.
- 대회 부수검증 엔진은 준비 중이다.
- 정정 요청과 운영자 업로드는 abuse control과 개인정보 정책 이후에 추가한다.
- 브라우저와 출처의 고신호 운영 오류는 개인정보 없이 fingerprint로 집계하며 자동 Issue는 같은 오류가 3회 누적된 뒤에만 생성한다. 자동 종료와 사용자 세션 추적은 하지 않는다.

## 13. 수용 조건

- React 렌더 오류는 보고 성공 여부와 무관하게 한국어 fallback을 표시하고 다시 시도할 수 있다.
- 브라우저의 렌더 오류·미처리 오류·미처리 Promise 거부와 출처의 구조 변경·인증 실패만 자동 집계하며, timeout·rate limit·offline·취소·일반 요청 실패는 제외한다.
- 동일한 안전 메타데이터는 하나의 fingerprint로 원자적으로 집계되고 3회부터 GitHub Issue를 한 번만 생성한다. 전달 결과가 모호하면 정확한 marker로 기존 Issue를 조정한다.
- 운영 오류 저장·게시 RPC는 service role 전용이고 메시지, stack, 검색어, 선수명, URL query/hash, HTML/body, 쿠키와 자격증명을 수집하지 않는다.
- 오류 보고와 출처 실패 상태 기록 자체가 실패해도 사용자 화면과 원래 refresh 오류 응답을 막거나 바꾸지 않는다.

- `김현동` 같은 동명이인 검색에서 후보가 별도 건으로 표시된다.
- 상단 부수 요약은 검증된 별칭과 미분류 기록별 영역 안에서 체계별 행과 부수 오름차순의 가로 세부 항목으로 구성하며, 체계·부수별 실제 기록을 입상과 참가로 나눠 센다. 항목을 누르면 해당 별칭 영역의 같은 체계와 부수 후보 목록으로 이동한다.
- 시·군·구 대회의 일반 `5부`, `6부`는 통합부수로 표시된다.
- 참가 종목 또는 관측 부수에 `여자`·`여성`이 있으면 내부적으로 `women`을 우선 적용하고 화면에는 `통합부수 여자6부` 형식으로 표시한다.
- T1~T7 기록은 디비전부수로 유지된다.
- 4강 이상만 입상 건수에 포함된다.
- 검색할 때 활성 출처 수와 현재 조회 중인 출처를 확인할 수 있다.
- 최초 저장 결과가 0건일 때만 출처 상세가 자동으로 펼쳐지고, 저장 결과가 있거나 출처 조회가 끝나면 접힌다. 실패한 출처는 5초 간격·화면당 최대 3회 범위에서 다시 시도할 수 있다.
- 출처 실패가 다른 출처와 저장 결과를 숨기지 않는다.
- 단일 또는 동명이인 참여 편집 후보마다 최근 출전 대회와 원문 종목명을 확인하고, 개수 제한 없이 직접 입력한 별칭 그룹에 배정할 수 있다. 단일 후보는 유일한 별칭 그룹에 기본 배정하고, 복수 후보는 자동 배정하지 않는다. 새 구분은 추천 목록의 무작위 별칭 하나로 시작하고 저장된 구분은 다음 진입에서 별칭과 기록 선택을 복원하며, 최근 기록 조회 실패 시 다시 불러올 수 있다.
- 한 사람만 확실히 아는 경우에도 별칭 한 개로 기록을 반영할 수 있고, 공개 이력에서 후보별 별칭을 확인한 뒤 최신 편집 전체를 근거와 함께 되돌릴 수 있다.
- production 배포 버전은 홈·검색 결과·선수 상세를 포함한 모든 페이지 하단에 `YYYY.WEEK.SEQ` 형식으로 표시된다.
- 모든 실제 기록은 원문 URL과 마지막 확인 시각을 제공한다.
